### 2. 配置文件 `application.yml`

已配好数据源与连接池、MyBatis-Plus、Sa-Token、Knife4j、日志。其中三处值得注意：

- **凭证已外置（2026-09-23 改）**：原先把云数据库口令直接写在 `application.yml`，而仓库是公开仓库，口令因此进了 git 历史。现改为**环境变量 → `application-local.yml`（已 gitignore）** 两级读取，`application.yml` 里只剩占位符，模板见同目录 `application-local.yml.example`。已实测：重新打包启动后调 `/api/v1/auth/login` 返回 200 并拿到真实 token。**注意两点**：①改文件不等于修好，只有轮换口令才能让历史里的旧口令失效（**2026-09-23 已轮换**，旧口令实测被服务端拒绝，见第二节第 9 条）；②**缺凭证不会启动失败**（实测确认，`@ConfigurationProperties` 对解析不了的占位符不报错），要到第一次访问数据库才暴露，排查连不上库时先看 `application-local.yml` 是否存在

### 6. `vcp-system` 模块（2026-09-23 新增）

这是第一个真正跑起来的业务模块，也是「登录 → 拿 token → 访问受保护接口」主链路的验证。

**代码规模**：entity 8 / mapper 8 / dto 10 / vo 8 / service 接口 6 + 实现 7 / controller 7 / 事件监听器 1。

**接口清单**（前缀 `/api/v1`）：

| 路径 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `/auth/login` | POST | 放行 | 登录，写 token 并往会话写 roleCode / orgId / studentId |
| `/auth/register` | POST | 放行 | 学生自助注册，注册即登录 |
| `/auth/logout` | POST | 登录 | 退出 |
| `/auth/me` | GET / PUT | 登录 | 查 / 改本人资料（只能改姓名、手机号、邮箱） |
| `/system/users` | GET / POST | `system:user:list` / `:create` | 用户列表与新增 |
| `/system/users/{id}` | PUT / DELETE | `system:user:update` / `:delete` | 修改与删除（逻辑删除） |
| `/system/users/{id}/status` | PUT | `system:user:update` | 启用 / 停用 |
| `/system/roles` | GET | `system:role:list` | 角色 + 权限清单（只读，角色不可增删改） |
| `/system/dicts` | GET | **仅需登录** | 字典，三种角色都要用，不能挂 `system:*` |
| `/system/students` | GET | 仅学校管理员 | 学生档案（前端暂无页面调用，为后续预留） |
| `/system/notifications` | GET / POST / DELETE | 读**仅需登录**；写 `system:notice:manage` | 通知公告 |
| `/system/notifications/{id}` `/read` | GET / PUT | 仅需登录 | 详情（顺带标已读）与标已读 |
| `/system/logs` | GET | `system:log:list` | 操作日志（只读，无写接口） |

**几个刻意的设计取舍**：

- **`sys_dict` 必须返回 `tone`**：前端 `stores/dict.js` 的 `load()` 是**整体替换**语义，
  接口不返回 `tone` 会把所有状态标签刷成灰色。这是「不报错但页面全变样」的典型静默失效。
- **通知按收件人一行存，用 `batch_no` 串批次**：`is_read` 天然是按人记的；
  删除时只有自己那一行的 id，不按批次整批删就会「删了但学生端还在」。
- **`operation_log` 不存 `role` 列**：由 `user_id` 实时关联推导，冗余存一列在角色调整后会失真。
- **登录 / 注册不采集请求参数**（`@OperationLog(params = false)`）：请求体里是明文密码，
  采集会把口令序列化进 `operation_log.params` 永久留存。
- **停用 / 删除自己会被拒绝**：管理员一旦把自己停掉，登录接口会以 20002 拒绝，
  而恢复又需要登录，等于系统再也进不去。
- **越权访问别人的通知报 10004 而不是 20003**：报「无权限」等于确认这条通知存在。
- **时间字段在服务端格式化成字符串**：日志页与通知页直接渲染 `{{ row.time }}` / `{{ row.date }}`，
  返回 `LocalDateTime` 会带上 ISO 的 `T`。

**验证方式**：本机启动后跑了 42 项端到端断言，全部通过——覆盖登录 / 注册 / 退出、
三类角色登录、按角色筛选用户、字典分组、日志落库与中文模块筛选、公告群发与整批删除、
学生越权被拒 20003、停用账号登录 20002、退出后 token 失效 20001、逻辑删除后列表不可见等。

**新增的前置脚本 `sql/05_backend_gap_fix.sql`**：前端要而 `02_schema.sql` 里没有的列，
全部是 `ADD COLUMN IF NOT EXISTS` + `ON CONFLICT DO NOTHING`，只做加法、可重复执行。
**不执行它，登录接口会直接报错**（`sys_user.last_login_at` 不存在）。

其中一处值得记下：字典色调必须按 `(dict_type, dict_key)` **精确指定**，不能只按 `dict_key` 匹配 ——
不同字典类型里有同名键（`CANCELED` 同时属于 `activity_status` 与 `signup_status`），
只按 `dict_key` 更新会把它们刷成同一种色调，而前端的取值并不相同（一个是 bad 红、一个是 mute 灰）。
这类错配不报错，只表现为「这个标签的颜色跟别处不一样」。

### 7. `vcp-org` 模块（2026-09-23 新增）

这是第二个真正跑起来的业务模块，负责组织基础信息、资质审核与启停。

**代码规模**：entity 1 / mapper 1 / dto 4 / vo 1 / service 接口 1 + 实现 2 / controller 1。

**接口清单**（前缀 `/api/v1`）：

| 路径 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `/orgs` | GET | `org:info:audit` | 学校管理员分页查询组织 |
| `/orgs/{id}` | GET | 登录 | 详情；学校管理员可查任意，组织管理员只能查本组织 |
| `/orgs/{id}` | PUT | 登录 | 更新组织资料；数据范围同详情 |
| `/orgs/{id}/audit` | PUT | `org:info:audit` | 资质审核，`APPROVE` / `REJECT`，驳回必须填理由 |
| `/orgs/{id}/status` | PUT | `org:info:audit` | 已审核组织在 `APPROVED` / `DISABLED` 间启停 |

**几个刻意的设计取舍**：

- **`DISABLED` 与 `REJECTED` 分离**：停用不改变资质结论，历史活动与时长数据继续保留；
  只有已通过审核的组织允许启停，待审核和驳回组织不能直接「启用」。
- **登录归属用端口接回**：`vcp-system` 定义 `OrgLookupPort`，`vcp-org` 提供实现；
  组织管理员登录后，会话写入 `orgId`，前端组织端页面不再只能回退到 id 1。
- **审核结果通知负责人**：新增单用户通知方法，不复用群发公告逻辑；
  审核通过/驳回各落一条系统通知，驳回理由写入正文。
- **组织资料更新不带状态字段**：状态、负责人账号、审核备注只能走对应接口，
  避免资料维护绕开状态机。
- **聚合指标通过 `OrgMetricsPort` 预留**：`vcp-org` 不直接访问活动与认证表；
  后续统计模块实现该端口后可填活动场次、签到率、通过率，未实现时返回 0。

**数据库补齐**：`05_backend_gap_fix.sql` 为 `org_info` 补了
`code` / `college` / `member_count` / `founded_at` / `audit_remark`，
并增加状态查询索引与「在用组织负责人」部分唯一索引。

**验证方式**：11 个 Maven 模块 `package` 全部通过；数据库脚本已在当前库实跑；
启动后实测 8 个组织分页返回、组织管理员登录得到 `orgId=1`、
组织管理员读取与更新本组织成功、学生读取/更新返回 20003、
启停往返后状态恢复 `APPROVED`、非法审核动作返回 10001 且状态保持 `PENDING`。

### 10. 演示数据放大与 `sql/07` 修复（2026-09-24）

`sql/07_demo_scale.sql` 是同学在提交 `0a668d7` 新增的演示数据放大脚本（初版 797 行，本次修复后 903 行），
**入库后从未执行过**。同学的 F4 审计指出 5 个演示数据缺口：规模差约 500 倍、

**脚本自身的三处缺陷（此前从未跑过，一跑就暴露）**

| # | 位置 | 缺陷与后果 | 修法 |
|---|---|---|---|
| 1 | `sql/07_demo_scale.sql:108` | `DATE '2015-01-01' + ((id * 137) % 2920)` 是 `date + bigint`，而 PostgreSQL 只有 `date + integer`、没有这个运算符 —— **脚本第一条 UPDATE 就报错**，整批回滚 | 改为 `(((id * 137) % 2920)::int)` |
| 2 | `sql/07_demo_scale.sql:381`（第五节报名上限） | 原为 `8 + ((a.id * 7919) % 32)`（8..39 场）→ 人均只参与 5.5 场、最高 9 场 ≈ 37.2 小时，**「五星志愿者（≥40 小时）」一档恒为空**，末尾自检第 3 项必然失败 | 改为 `16 + ((a.id * 7919) % 30)`（16..45 场） |
| 3 | 新增一节（`sql/07_demo_scale.sql:595` 起） | 只靠调大报名数补不出五星档：总报名会冲到约 3 万条，而前端原型只有 12,480 条 | 新增「十之二、把高活跃学生定向补进五星档」 |

- **缺陷 2 的安全边界**：已结束活动约 85% 的报名会变成 `COMPLETED`，
  45 × 0.85 = 38.25 < 名额下限 40，所以自检第 4 项（`signed_count > max_count`）仍然安全
- **第十之二节为什么必须「定向补」**：一次报名要过三层折算
  （85% COMPLETED × 90% 非缺勤 × 75% 时长审核通过 ≈ 57%）才变成一条有效时长，
  每条约 4 小时，40 小时需要约 18 次报名；改为对累计 32..40 小时的学生
  定向补 4 场 ≥4 小时的活动，做法与第十节给演示账号补记录一致
- **另修一处幂等性漏洞**：第十节（演示账号补记录）与新增的第十之二节原先没挂
  `should_scale` 守卫，重跑会给学生 1 再补 6 场、五星档持续膨胀（现已挂上，见

## 三、关键决策与理由

| 决策 | 理由 |
|---|---|
| `vcp-dependencies` **不继承**聚合根 | 否则与聚合根的 BOM 导入形成循环，Maven 无法读取工程 |
| **Flyway 暂时关闭** | 表结构在开发期会频繁变动，而 Flyway 的已执行脚本受 checksum 保护、不可再改，此时开启会处处报错。待表结构稳定后，把 `02_schema.sql`/`03_init_data.sql` 复制到 `db/migration/` 并改名为 `V2__`/`V3__` 即可开启 |
| 主键用 `BIGSERIAL` + `id-type: auto` | 数据库自增，与建表脚本和初始数据一致 |
| 时间类型用 `TIMESTAMP`（非 `timestamptz`） | 沿用原始设计。单时区部署无影响；若将来跨时区需改 |
| **并非所有表都有 `deleted`** | 关联表、流水/日志表加逻辑删除没有意义、只增加查询负担。详见 `sql/README.md` 第三节 |
| 演示数据用**确定性算法**（取模而非 `random()`） | 保证三个成员执行后看到完全一致的演示效果 |
| ~~数据库口令直接写在 `application.yml`~~ **2026-09-23 已撤销** | 当初是团队决定，**代价是口令进了 git 历史**。现已改为环境变量 / `application-local.yml` 外置（见第二节第 2 条），并已于 2026-09-23 **轮换口令**：旧口令实测被服务端拒绝，历史里的旧口令已失效（见第二节第 9 条） |

## 七、附：状态枚举码表（参考信息，前端无需参与）

数据库统一存**英文大写码**，中文由 `sys_dict` 表翻译。

| 字典类型 | 码 → 中文 |
|---|---|
| `activity_status` | `DRAFT` 草稿 / `PUBLISHED` 已发布 / `CLOSED` 已结束 / `CANCELED` 已取消 |
| `signup_status` | `PENDING` 待审核 / `APPROVED` 已通过 / `REJECTED` 已驳回 / `CANCELED` 已取消 / `COMPLETED` 已完成 |
| `attendance_status` | `NOT_SIGNED` 未签到 / `SIGNED_IN` 已签到 / `SIGNED_OUT` 已签退 / `ABNORMAL` 异常 / `ABSENT` 缺勤 |
| `duration_status` | `PENDING_SUBMIT` 待提交 / `PENDING_AUDIT` 待审核 / `APPROVED` 已通过 / `REJECTED` 已驳回 |
| `org_status` | `PENDING` 待审核 / `APPROVED` 已通过 / `REJECTED` 已驳回 / `DISABLED` 已停用（2026-09-23 由 `sql/05` 补） |
| `notification_type` | `SIGNUP` 报名结果 / `DURATION` 时长审核 / `SYSTEM` 系统公告 |
| `audit_action` | `SUBMIT` 提交 / `APPROVE` 通过 / `REJECT` 驳回（注意与状态值的 `APPROVED`/`REJECTED` 不同形） |
| `attachment_biz_type` | `ACTIVITY` 活动封面 / `ORG` 组织资质 / `AVATAR` 用户头像 |
| `user_status` | `ACTIVE` 正常 / `DISABLED` 已停用（2026-09-23 由 `sql/05` 补；`sys_user.status` 库里存 1/0，由服务层翻译） |
