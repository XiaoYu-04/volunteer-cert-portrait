## 二、已完成的工作

### 1. 修复后端工程（此前完全无法构建）

| 问题 | 说明 |
|---|---|
| **依赖管理循环（致命）** | `vcp-dependencies` 作为 BOM 被聚合根导入，而它的 `parent` 又指向聚合根，互相引用成环。Maven 直接拒绝读取整个工程，11 个模块一个都读不出来。已改为独立 BOM（不继承聚合根），并在 pom 里加注释说明**不能改回去** |
| **`spring-boot-starter-aop` 不存在** | Boot 4 已将其改名为 `spring-boot-starter-aspectj`，旧坐标在 4.x 下没有发布（最后版本停在 3.5.16）。已修正 |
| **启动类缺失** | pom 里配了 `mainClass=com.vcp.VcpApplication`，但模块里只有 IntelliJ 模板 `Main.java`。注意：这不影响构建（repackage 照样成功），只在 `java -jar` 时才 ClassNotFound。已补上启动类 |
| **10 个模板 `Main.java`** | IntelliJ 自动生成的 `Hello and welcome!` 模板，10 个文件内容完全相同，会让每个 jar 里都出现 `com.vcp.Main`。已全部删除 |
| **无 `.gitignore`** | 构建产物 `target/`（33MB）会被误提交。已补 |

### 2. 配置文件 `application.yml`

已配好数据源与连接池、MyBatis-Plus、Sa-Token、Knife4j、日志。其中两处值得注意：

- **口令必须加引号**：`041014` 不加引号会被 YAML 当作**八进制整数**解析成 `16908`（已实测确认），口令就错了。写成 `"041014"` 才是字符串
- **`id-type` 必须是 `auto`**：MyBatis-Plus 默认是 `assign_id`（雪花 ID），会由应用生成主键、绕过数据库序列，与建表脚本的 `BIGSERIAL` 以及初始数据里显式写入的 `id=1,2,3` 冲突

### 3. 接口文档 Knife4j

已接入并**实测通过**：`/doc.html` 返回 200、`/v3/api-docs` 的标题/描述/版本正确、`/knife4j/config` 返回 200。

一个坑记录在此：`knife4j.enable` 默认为 `false` 且没有 `matchIfMissing`，不显式开启的话**增强能力（接口调试、过滤）会静默失效，但 `/doc.html` 仍能打开**，很容易误判为已接好。

验证过程发现并修复了 11 处缺陷，其中 3 处是实跑才能暴露的：

## 三、关键决策与理由

| 决策 | 理由 |
|---|---|
| `vcp-dependencies` **不继承**聚合根 | 否则与聚合根的 BOM 导入形成循环，Maven 无法读取工程 |
| **Flyway 暂时关闭** | 表结构在开发期会频繁变动，而 Flyway 的已执行脚本受 checksum 保护、不可再改，此时开启会处处报错。待表结构稳定后，把 `02_schema.sql`/`03_init_data.sql` 复制到 `db/migration/` 并改名为 `V2__`/`V3__` 即可开启 |
| 主键用 `BIGSERIAL` + `id-type: auto` | 数据库自增，与建表脚本和初始数据一致 |
| 时间类型用 `TIMESTAMP`（非 `timestamptz`） | 沿用原始设计。单时区部署无影响；若将来跨时区需改 |
| **并非所有表都有 `deleted`** | 关联表、流水/日志表加逻辑删除没有意义、只增加查询负担。详见 `sql/README.md` 第三节 |
| 演示数据用**确定性算法**（取模而非 `random()`） | 保证三个成员执行后看到完全一致的演示效果 |
| 数据库口令直接写在 `application.yml` | 团队决定。**代价：口令已进入 git 历史，即使以后删除该行也仍可从历史中翻出** |

## 七、附：状态枚举码表（参考信息，前端无需参与）

数据库统一存**英文大写码**，中文由 `sys_dict` 表翻译。

| 字典类型 | 码 → 中文 |
|---|---|
| `activity_status` | `DRAFT` 草稿 / `PUBLISHED` 已发布 / `CLOSED` 已结束 / `CANCELED` 已取消 |
| `signup_status` | `PENDING` 待审核 / `APPROVED` 已通过 / `REJECTED` 已驳回 / `CANCELED` 已取消 / `COMPLETED` 已完成 |
| `attendance_status` | `NOT_SIGNED` 未签到 / `SIGNED_IN` 已签到 / `SIGNED_OUT` 已签退 / `ABNORMAL` 异常 / `ABSENT` 缺勤 |
| `duration_status` | `PENDING_SUBMIT` 待提交 / `PENDING_AUDIT` 待审核 / `APPROVED` 已通过 / `REJECTED` 已驳回 |
| `org_status` | `PENDING` 待审核 / `APPROVED` 已通过 / `REJECTED` 已驳回 |
| `notification_type` | `SIGNUP` 报名结果 / `DURATION` 时长审核 / `SYSTEM` 系统公告 |
| `audit_action` | `SUBMIT` 提交 / `APPROVE` 通过 / `REJECT` 驳回（注意与状态值的 `APPROVED`/`REJECTED` 不同形） |
| `attachment_biz_type` | `ACTIVITY` 活动封面 / `ORG` 组织资质 / `AVATAR` 用户头像 |
