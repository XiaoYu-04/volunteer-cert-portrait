
# 高校志愿服务时长认证与公益画像数据分析系统  
## 项目开发步骤与三人小组分工方案

---

## 一、最终选题信息

### 1.1 项目名称

**基于多角色审核的高校志愿服务时长认证与公益画像数据分析系统设计与实现**

可简化为：

**高校志愿服务时长认证与公益画像数据分析系统设计与实现**

### 1.2 技术栈限定

- 后端：Spring Boot
- 前端：Vue
- 数据库：PostgreSQL
- 其他建议技术：
  - Vue 3
  - Vite
  - Pinia
  - Vue Router
  - Axios
  - Element Plus
  - ECharts
  - Spring Security 或 Sa-Token
  - MyBatis-Plus 或 Spring Data JPA
  - JWT 登录认证

### 1.3 项目定位

本系统不是普通的“活动管理系统”，而是围绕：

- 志愿活动发布
- 学生报名审核
- 活动签到签退
- 服务时长记录
- 多角色时长审核
- 学生公益画像
- 志愿服务数据分析

形成一个完整的志愿服务闭环管理系统。

### 1.4 项目亮点

1. 多角色审核机制：学生、组织管理员、学校管理员。
2. 志愿服务全流程管理：发布、报名、签到、签退、时长认定。
3. 数据看板：活动趋势、签到率、学院排名、活动类型占比。
4. 学生公益画像：根据志愿时长、活动类型、参与频率生成画像。
5. 避免普通活动管理系统的高重复率问题。

示例统计 SQL 场景：

```sql

FROM service_duration
WHERE status = '已通过'
GROUP BY college
ORDER BY total_duration DESC;
```

## 十、风险控制

### 10.1 可能遇到的问题

| 问题 | 风险 | 解决方法 |
|---|---|---|
| 功能做太多 | 做不完 | 砍掉证书、积分商城等扩展功能 |
| 状态字段混乱 | 流程出错 | 先统一状态机 |
| 前后端联调慢 | 进度延误 | 先约定接口文档 |
| 测试数据不足 | 答辩效果差 | 提前构造模拟数据 |
| 图表不会做 | 亮点不足 | 先做简单折线图、饼图、柱状图 |
| 权限设计复杂 | 开发困难 | 先做简单角色判断 |

### 10.2 最低可运行版本

如果时间紧张，必须保证以下功能完成：

1. 登录。
2. 活动列表。
3. 活动报名。
4. 报名审核。
5. 签到签退。
6. 时长审核。
7. 简单数据看板。

这些完成后，项目已经可以作为毕业设计正常答辩。

## 十二、总结

本项目最终定位为：

> **基于多角色审核的高校志愿服务时长认证与公益画像数据分析系统**

项目核心不是简单管理活动，而是解决：

- 志愿活动如何发布
- 学生如何报名
- 报名如何审核
- 签到签退如何记录
- 服务时长如何认证
- 学生公益画像如何生成
- 学校如何通过数据分析掌握志愿服务情况

三人小组建议分工：

- **成员 A：后端核心 + 数据库**
- **成员 B：前端页面 + 数据可视化**
- **成员 C：业务流程 + 测试 + 文档答辩**

该选题具备：

- 较低重复率
- 明确业务闭环
- 多角色协作
- 数据分析亮点
- 适中数据库复杂度
- 适合三人小组完成
- 适合 Spring Boot + Vue + PostgreSQL 技术栈

可以作为最终毕业设计选题。
