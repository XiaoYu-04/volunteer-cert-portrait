## 一、实测数据现状（阈值定档的依据）

| 指标 | 实测结果 |
|---|---|
| 学生累计有效时长 | 最小 **0**、平均 **5.6**、最大 **14.4** 小时；其中 4 人为 0 |
| 已完成活动次数 | 1~4 次（1次 6 人 / 2次 6 人 / 3次 13 人 / 4次 6 人） |
| 各分类参与人次 | 文化传播 17 / 大型赛事 14 / 校园服务 14 / 环保公益 13 / 社区服务 12 / 助老服务 11 |
| **同一分类下的参与次数** | **参与 1 次的有 79 组，参与 2 次的仅 1 组** |
| 首末次活动跨度 ≥ 30 天 | 14 人 |

**两个关键发现：**

1. **演示数据里学生几乎不在同一分类重复参与**（79/80 组只参与过 1 次）。因此
   "同一分类参与 ≥2 次才给类型标签"这类规则在当前演示数据上**几乎等于失效**
   （只有 1 个学生会拿到类型标签）。
2. **文化传播是人次最多的分类，但文档给出的 6 个标签名里没有它**，也没有"助老服务"。
   这两类参与者将拿不到任何类型标签。

## 二、公益等级方案

存储位置：`student_info.public_welfare_level`（`VARCHAR(50)`，存中文等级名）
计算依据：`student_info.total_duration`（即审核通过的时长汇总）

### 方案 A：演示尺度（推荐用于毕设答辩）

| 等级 | 累计有效时长（小时） | 当前演示数据下的人数 |
|---|---|---|
| 普通志愿者 | `x < 3` | 6 |
| 一星志愿者 | `3 ≤ x < 6` | 12 |
| 二星志愿者 | `6 ≤ x < 10` | 10 |
| 三星志愿者 | `10 ≤ x < 20` | 3 |
| 四星志愿者 | `20 ≤ x < 40` | 0 |
| 五星志愿者 | `x ≥ 40` | 0 |

**优点**：答辩时能展示出 4 个档位，等级分布图不会是一片"普通志愿者"。
**代价**：3 小时就是一星，比现实标准低得多。

### 方案 B：贴近现实标准

沿用中国青年志愿者星级标准（一星 100h / 二星 300h / 三星 600h / 四星 1000h / 五星 1500h），
另加"普通志愿者"兜底。

**优点**：说得出处，答辩时经得起追问。
**代价**：当前演示数据下 **31 人全部是"普通志愿者"**，等级分布图完全看不出层次。

### 建议

**推荐方案 A，并把阈值做成可配置常量**（例如放在 `vcp-portrait` 的枚举或配置项里），
在论文里注明"本项目为便于演示采用较低的阈值，实际部署时应按学校标准调整"。
这样既有演示效果，又能说清楚取舍。

## 三、公益标签方案

存储位置：`student_profile.tags`（`VARCHAR(255)`，**逗号分隔字符串**，非数组非关联表）
可同时拥有多个标签。

| 标签 | 判定条件 | 当前演示数据下的人数 |
|---|---|---|
| 热心志愿者 | 累计有效时长 `> 0` | 27 |
| 长期坚持型 | 已完成活动次数 `≥ 3` | 19 |
| 校园服务型 | 见下方"类型标签" | — |
| 社区服务型 | 同上 | — |
| 环保行动型 | 同上 | — |
| 大型活动型 | 同上 | — |
| **助老服务型** | **需要新增的标签名** | — |
| **文化传播型** | **需要新增的标签名** | — |

### 类型标签（互斥，最多一个）

取**参与次数最多**的活动分类，映射为标签：

| 活动分类 | 对应标签 |
|---|---|
| 校园服务 | 校园服务型 |
| 社区服务 | 社区服务型 |
| 环保公益 | 环保行动型 |
| 大型赛事 | 大型活动型 |
| 助老服务 | **助老服务型**（文档未给出，需新增） |
| 文化传播 | **文化传播型**（文档未给出，需新增） |

并列时用**分类 id 升序**打破，**不要用中文名排序** —— 中文串的排序结果依赖数据库
collation，会导致不同机器执行结果不一致。

### 关于"是否要求同分类 ≥2 次"

- **要求 ≥2 次**：语义更严谨（避免"只参加过一次就贴类型标签"），但当前演示数据下
  **只有 1 个学生**能拿到类型标签，画像页会显得空。
- **不要求下限**：一定能产出标签，但可能基于单次活动。

**建议**：采用"**不要求下限**"，同时**改进演示数据**（见第四节），让学生的参与有
分类倾向。这样既严谨又能展示效果。

### 可选增强（非必需）

"长期坚持型"可加时间跨度条件（如 `≥3 次` 且 首末次活动跨度 `≥90 天`），
语义上更贴近"坚持"。当前演示数据下有 14 人跨度 ≥30 天，加上次数条件后人数会下降。

## 四、建议一并改进演示数据

当前 `04_demo_data.sql` 生成报名时，学生是按取模**均匀打散**到各活动的，
导致每个人的参与分类几乎都不重复（79/80 组只参与 1 次）—— 这**不像真实志愿者**，
真实的志愿者会集中在自己偏好的领域反复参与。

**建议改法**：给每个学生预设 1~2 个"偏好分类"，让约 60% 的报名落在偏好分类内。
这样：
- 类型标签才有意义（同分类参与次数能拉开）
- "活动类型偏好"这一画像维度才看得出来
- 看板的"活动类型占比图"也更真实

改动仅限 `04_demo_data.sql` 的报名生成逻辑，需要重新执行验证。

## 五、落地方式

| 项 | 位置 |
|---|---|
| 等级计算 | `vcp-portrait` 模块，输入 `student_info.total_duration`，输出等级名写回 `student_info.public_welfare_level` |
| 标签计算 | `vcp-portrait` 模块，聚合 `activity_signup`（`status='COMPLETED'`）+ `volunteer_activity` + `activity_category`，写回 `student_profile.tags` |
| 重算时机 | 建议：时长审核通过后触发重算（`vcp-certification` 审核动作发事件 → `vcp-portrait` 监听）；或提供手动重算接口 + 定时任务兜底 |
| 阈值常量 | 建议集中定义，便于调整（不要散落在 SQL 与 Java 两处） |

> 注意 `student_profile.total_duration` 与 `student_info.total_duration` 含义重复，
> 建议**以 `student_info` 为权威值**，`student_profile` 仅作画像快照。
> 此项也列在 `docs/后端进展与待办.md` 的 P0 待定事项里。

## 六、已确认的三项决策

1. **公益等级用哪套阈值？** → **方案 A（演示尺度）**。理由：方案 B 下当前 31 人全部是
   "普通志愿者"，答辩时等级分布图看不出层次。阈值做成可配置常量，论文中注明取舍。
2. **是否新增"助老服务型""文化传播型"？** → **新增**。否则这两类参与者拿不到类型标签，
   而文化传播恰是人次最多的分类。
3. **类型标签是否要求同分类 ≥2 次？** → **不设下限**，同时**改进演示数据**为学生预设偏好分类。
   理由：设下限会让当前演示数据下只有 1 个学生拿到类型标签。

### 落地后的实测效果（PostgreSQL 18.6）

| 项 | 结果 |
|---|---|
| 等级分布 | 普通 13 / 一星 6 / 二星 7 / 三星 5 —— **4 个档位可见** |
| 同分类参与次数 | 1 次 33 组、2 次 22 组（改进前为 79 / 1） |
| 各分类人次 | 文化传播 17、助老服务 14、大型赛事 14、社区服务 12、校园服务 11、环保公益 9 |
| 18 项一致性自检 | 全部为 0 |
