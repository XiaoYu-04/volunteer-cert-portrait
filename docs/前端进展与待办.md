### 10. dev server 代理目标改为可配置（2026-09-24）

`vite.config.js` 的 proxy target 原先**写死** `http://10.0.20.91:8080`（某台机器的内网 IP）且已随提交入库，
那台机器一关机或换 IP，所有人的 dev server 就集体连不上（mock 又是关的，没有后端就跑不起来）。现改为：

- 导出改成函数式 `defineConfig(({ mode }) => {...})`，用 `loadEnv(mode, process.cwd(), '')` 读环境变量，
  target 取 `env.VITE_API_TARGET || 'http://127.0.0.1:8080'`
- `.env.development` 补注释说明用法（可选，默认 `http://127.0.0.1:8080`；联调时放 `.env.local` 覆盖，
  **不要把某人的内网 IP 写进入库文件**），`VITE_API_BASE_URL=/api` 与 `VITE_USE_MOCK=false` 保持不动
- 已实测：不设变量时解析出 `http://127.0.0.1:8080`；在 `.env.local` 里另设 `VITE_API_TARGET`
  能覆盖生效（用局域网地址验证过）

> ⚠️ **代理配置不是热更新**：改完 `vite.config.js` 必须让 dev server 重启才会生效 —— 手动停掉再 `npm run dev`
> 一次最保险；不重启的话代理仍是旧目标，会出现「配置改了却还连旧机器」的错觉。

## 三、关键决策与理由

### 1. 纯手写组件，不引入 Element Plus

原型是一套**完整的设计系统**（零圆角、墨线分隔、印章式标签），与 Element Plus 的默认视觉冲突很大。
用 Element Plus 需要大量样式覆盖，且很难完全摆脱它的观感。手写组件虽然工作量大，但视觉一致性最好，
答辩时也讲得清"这部分是自己实现的"。

### 2. 保持 JavaScript，不迁 TypeScript

脚手架现成，省下的时间用于多铺页面。架构文档虽规划了 TS，但毕设答辩中 TS 并非必需项。

### 3. 用原生 CSS，不引入 Sass

原型本身就是纯 CSS，加 Sass 只会多一个构建依赖，没有实际收益。

### 4. 图表内的柱状元素保留轻微圆角

原型对柱状图用了 `borderRadius: [6,6,0,0]`，与页面 UI 的"零圆角"看似矛盾。
**这是原型的刻意选择**（页面 chrome 零圆角、图表内元素轻微圆角），已照搬并在代码注释与 README 中标注，不要"统一"掉。

### 5. Mock 分流：切换后端只改一个环境变量

后端当时未就绪，但不能把假数据散落在页面里。做法是 `api/*.js` 按真实契约书写，
由 `utils/request.js` 按 `VITE_USE_MOCK` 分流。后端就绪后改 `.env` 一个开关即可，页面代码零改动
（dev 现已切到真实后端；纯前端演示仍可让 `.env` 走 mock）。

### 6. 状态枚举以后端为权威

本轮核对 `sql/02_schema.sql` 的列注释与 `sql/03_init_data.sql` 的 `sys_dict` 种子数据，
发现前端有 3 处码值对不上，**已按后端对齐**（后端脚本已在 PostgreSQL 18.6 实跑验证，是权威来源）：

| 字典类型 | 前端原值 | 已改为（后端值） |
|---|---|---|
| `attendance_status` | `UNSIGNED` | `NOT_SIGNED` |
| `notification_type` | `SYSTEM`/`ACTIVITY`/`AUDIT` | `SIGNUP`/`DURATION`/`SYSTEM` |
| `audit_action` | 缺 `SUBMIT` | 补上 `SUBMIT` |

顺带确认了两项**本来就一致、无需改动**的对接点：

- 认证头：后端 `sa-token.token-name: Authorization` + `token-prefix: Bearer`，与前端 `Authorization: Bearer <token>` 一致
- 路径前缀：后端未配 `context-path`，前端经 Vite 代理 `/api` → `8080`，到达后端即 `/api/v1/...`，与架构文档一致

### 7. 注册账号跨刷新持久化，其余实体保持内存态

mock 数据活在内存里，整页刷新会重置模块。注册产生的新账号如果不落盘，会出现
"注册 → 刷新 → 被踢回登录页，且新账号再也登不回来"。

只持久化**账号**这一项（`localStorage` 的 `vcp_mock_extra_users`）；其余实体（活动、报名、时长…）
保持内存态，刷新即回到干净的种子数据，方便反复演示同一条流程。想彻底重置清掉该 key 即可。

### 8. 代理目标放进环境变量，而不是写死在 `vite.config.js`

dev server 的 proxy target 曾写死成某台机器的内网 IP，那台机器关机或换 IP 所有人都连不上，
而 `.env.development` 的 `VITE_USE_MOCK=false` 已入库，没有后端页面直接起不来。
改为读 `VITE_API_TARGET`、**默认打本机 `http://127.0.0.1:8080`**：各人跑各自的后端，
要和队友联调时在 `.env.local` 里覆盖（已 gitignore）。

两个坑记在这里：

- `vite.config.js` 里 **`process.env` 拿不到 `.env` 文件里的变量**，必须用 `loadEnv(mode, process.cwd(), '')`
  读；第三个参数传 `''` 是为了把 `VITE_` 前缀之外的变量也一并加载
- **`.env.local` 的优先级低于 `.env.development`**（加载顺序 `.env` → `.env.local` → `.env.[mode]` →
  `.env.[mode].local`，后者覆盖前者，Vite 8.3.0 实测）。所以 `.env.local` 只适合补 `.env.development`
  里没有的变量（如 `VITE_API_TARGET`）；要覆盖 `VITE_USE_MOCK` 这种已有值，得用 `.env.development.local`
  （同样被 gitignore）

### P1：走查发现的缺陷（C3 产出，2026-09-24）

> 三个都是 **mock 数据侧**的问题，真后端不受影响 —— 但 mock 正是「纯前端独立演示」

| # | 缺陷 | 证据与成因 | 修法 |
|---|---|---|---|
| 1 | **个人中心手机号预填脱敏值 → 不改动就存不了** | 实测：预填 `138****3300`，直接点「保存修改」报「请填写 11 位手机号」，**保存失败**，手动清空后才能存。成因：`mock/data/dataset.js` 的 `users[].phone` 存的就是脱敏串，`ProfileView.vue:19` 把它预填进表单，而 `:31` 的校验是 `/^1\d{10}$/`。真库存的是完整号码（`13800000003`），`SessionVO.phone` 不脱敏 | mock 的 `users[].phone` 改存完整号码（与真库一致；mock 不是安全边界） |
| 2 | **签到管理「实得时长」与签到签退时间不自洽** | 实测：签到 `08:45` → 签退 `12:05`（差 3 小时 20 分），同一行「实得时长」写 **4 小时**。成因：`dataset.js:913` 写死 `hours: status === 'SIGNED_OUT' ? activities[0].hours : 0`，取的是活动声明时长、与钟点无关。**后端口径是 `(签退 − 签到)/3600`**（`AttendancePolicy`，2 位小数、封顶活动预计时长的 1.5 倍），按后端算该行应是 **3.33** | 让生成的 `signInAt`/`signOutAt` 正好卡住活动时长（如 `08:00 → 12:00`），**保持 4.00 不变** —— 不动聚合数字，比「照后端公式算」风险小 |
| 3 | **mock 分类 `remark` 全为空串** | `dataset.js:163` 写死 `remark: ''` → 分类管理页「说明」列 6 行全 `—`；真库 6 条都有值（B20-2 补列后 `sql/07` 回填过） | 给 6 个分类填上与真库同风格的说明文字 |

累计时长）与**枚举覆盖**（四种签到状态都出现），**不覆盖同一行内字段之间的一致性**。

（`docs/下一步待办.md` 第 26 项）。
