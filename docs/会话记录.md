- **口令存储**：新增 `PasswordUtils`（BCrypt 强度 10）。口令读写全工程只经这一个类 ——
  登录校验、注册写入、管理员新增用户、本人改密、管理员重置五处。

- **登录失败锁定**：`LoginAttemptGuard` 内存 `ConcurrentHashMap`，连续 5 次失败锁 15 分钟、成功即清零。
  三个刻意取舍：单实例内存实现（重启即清空）、不落表列也不上 Redis、
  **对不存在的用户名同样计数**（否则「第 5 次会不会被锁」就成了账号是否存在的探针）。
  锁定判定排在**查库与口令校验之前**（否则锁定期间正确口令能登录，两条路径耗时差还会变成旁路信息）。
- **本人改密** `PUT /api/v1/auth/password`：改完踢掉该账号其它会话、**保留当前会话**
  （否则用户会以为改密失败）。
- **管理员重置** `PUT /api/v1/system/users/{id}/password`：口令可空（空即重置为 `123456`），
  重置后踢掉该账号**全部**会话 —— 重置的典型场景就是口令外泄。
- **新错误码** `ACCOUNT_LOCKED(20004)` / `OLD_PASSWORD_ERROR(20005)`，
  **刻意不进前端 `UNAUTHORIZED_CODES`**，免得被前端统一拦截成「登录已过期」。
- **前端**：新增共享组件 `ChangePasswordDialog.vue`，入口三处（学生个人中心「账号安全」、
  组织端/学校端控制台侧栏 —— 这两个角色没有个人中心页、这是他们唯一的自助改密入口、
  用户管理操作列「重置密码」）；`UserManageView` 初始口令框 `type="text"` → `password`，

### 本会话踩过的坑（下次直接照抄）

- **Maven 直连中央仓库超时**。解决办法：临时 settings 走阿里云镜像
  （`%TEMP%\vcp-settings-aliyun.xml`，本机无 `~/.m2/settings.xml`），命令：

  ```powershell
  mvn -s "$env:TEMP\vcp-settings-aliyun.xml" "-Dmaven.repo.local=C:\Users\lsy04\.m2\repository" `
      "-Dmaven.legacyLocalRepo=true" -DskipTests -B package
  ```

  `-Dmaven.legacyLocalRepo=true` **必须用双引号包住**，否则被 PowerShell 拆坏。
- **PowerShell 里 `$2` 会被当变量吃掉**：给数据库脚本传 BCrypt 密文时，SQL 一律用**单引号**包裹。
- **PS 5.1 按 GBK 读 `.ps1` 文件**，中文注释会导致解析失败 → 脚本里的标签用纯 ASCII。
- **查库输出的中文乱码**：`chcp 65001` + `[Console]::OutputEncoding = UTF8`，
  java 还要加 `-Dstdout.encoding=UTF-8`。
- **本机连云库要提权**：沙箱默认拦出网，`java -cp postgresql-42.7.13.jar ...` 会报
  `SocketException: Permission denied: getsockopt`，需以提权方式重跑。
- **浏览器自动化**：`tab.getAXState()` 偶发只返回空壳，`reload()` 后即正常；
  要拿输入框 `type` 这类 AX 树看不到的属性，用 `tab.playwright.evaluate(...)` 直接查 DOM。

#### ③ 修 B30：给注册链路补上 `college`（后端 8 个文件 + 前端 3 个文件）

- **缺陷**：`student_info` 的 `college` / `major` / `class_name` 三列**全后端没有写入入口** ——
  建档只写 `user_id`、占位学号（`S` + 六位零填充 userId）与 `total_duration`，三列恒为 null。
  而学院是**分组键**：`analytics` 的 `selectCollegeStats` 按 `college IS NOT NULL AND college <> ''` 分组
  （看板「各学院志愿时长排名」），学生档案列表与时长列表也各有「学院」列 —— 学院为 null 的学生全落进空分组。
- **本轮改法**（自上而下一条链）：
  ① `RegisterDTO` 加 `college`；
  ② `AuthServiceImpl.register` 校验它**必须命中字典的启用项**；
  ③ `StudentArchiveRegistrar.ensureArchive(userId, college)` 写进 `student_info.college`；
  ④ 前端注册表单加学院下拉，选项来自新接口。
- **口径：学院不接受自由文本。** 同一学院一旦出现第二种写法，「按学院统计」就会把它算成另一个学院 ——
  所以下拉框与校验**共用同一份字典**，学院清单不写死在代码里（加学院是数据维护动作，写死意味着要发版）。
- 两个容易踩的实现细节：
  - `StudentArchiveRegistrar` 的**两个重载各标了一次 `@Transactional`** —— 类内自调用不走 Spring 代理，
    只在双参方法上标注的话，管理员那条路径会**静默地跑在没有事务的连接上**，建档失败时账号已经提交，
    留下「有账号、无档案」的孤儿。

  灌完**必须**把 `BIGSERIAL` 序列推到 `MAX(id)`（否则第一次插入就撞主键）。
- **`TRUNCATE ... RESTART IDENTITY CASCADE` 一把清 16 张表**：`RESTART IDENTITY` 让自增列归零，
  `CASCADE` 自动带上外键引用；只清数据、不动结构。
- **清库会清掉「增量脚本回填到行上」的值**：`05` / `06` 这类脚本执行过一次就不会自动重跑，
  重灌基础数据后要手动补跑（`sql/10` 头部已写明），否则字典色调、分类 code 这些「补出来的列值」会静默变空。
- **字典的「空类型」不能下推给 SQL**：`eq(dict_type, null)` 在 MyBatis-Plus 里是「不加条件」，
  传空值会返回全部字典项 —— 所以 `listByType` 里先挡空值。
- **类内自调用不走 Spring 代理**：重载方法要各自标 `@Transactional`，否则「看起来有事务」的那条路径其实没有。
- **加字段别顺手加 `@NotBlank`**：本轮的学院非空判定要查字典，注解表达不了；校验与文案都放 Service。
- **分组键不接受自由文本**：学院这类字段一旦出现第二种写法，「按分组统计」就分裂成两组；下拉与校验必须共用同一份字典。
- **验证脚本比代码先落盘时，别急着写「实测通过」**：本轮文档初稿写在打包重启之前，当时 jar 还是 13:37 那份、
  进程还是 pid 46468，于是初稿只能把「已修」限定在代码层面；打包重启后才补上 11/11 的实测结论。
  证据链要按 jar 时间戳与进程 pid 核，缺哪一环就写清楚缺哪一环。

### 要点

#### ① 学院即字典行：不新建表，管理端与注册页读同一份数据

- 学院**不是独立表**，是 `sys_dict` 里 `dict_type = 'college'` 的字典行（`dict_key` = `dict_value` = 学院名，
  `sort` 排序，`status` 1 / 0）。不新建表的理由：注册页下拉、注册校验、按学院筛学生与组织，全都按「学院名」
  这一列匹配，多一张表只会多一份可能与字典漂移的名字清单。
- **两条读路径的口径刻意不同**：管理端 `GET /api/v1/system/colleges` **不过滤 `status`** —— 管理页要能看到
  停用项并把它启用回来，否则停用等于「从列表里消失」，没有任何入口能改回去；注册页那份 `GET /api/v1/auth/colleges`
  只返回启用项（注册页不该选到停招的学院）。
- **删除是物理删除**（`sys_dict` 没有 `deleted` 列，字典行的下架手段本来是停用），所以只用于「建错了、还没被引用」的行；
  占用校验挡在前面：学院下还有学生或组织时拒绝，文案带具体数量（「该学院下还有 N 名学生、M 个组织，不能删除」）——
  只说「不能删除」用户会反复试，说清「还有 3 名学生」才知道该先去哪里清理。
- 占用校验要跨模块取组织数：`vcp-system` 定义 `OrgCollegeCountPort`、`vcp-org` 提供实现，调用方用
  `ObjectProvider.getIfAvailable()` 取，取不到或查询失败时 `orgCount` 一律按 0（缺这一列只影响展示，
  不该让整个列表页打不开）。依赖方向仍是 `vcp-org → vcp-system`，**没有反向依赖**，与 `OrgLookupPort` 同一套路。

#### ② 计数不逐行查：两次 GROUP BY，删除校验复用同一份结果

- 列表页一次要全部学院的学生数与组织数，逐学院 COUNT 就是 N+1：学生数走 `student_info` 一次 GROUP BY
  （排除 `college` 为 null / 空串的行，否则会多出一个并不存在的「学院」分组），组织数走端口的一次 GROUP BY。
- 删除前的占用校验复用同一份聚合结果（端口只有 `countByCollege()` 一个方法）—— 删除是低频操作，
  不值得为它把端口接口撑大。
- 实测（pid 102528）：`GET /api/v1/system/colleges` 返回 5 行、字段齐全 —— `studentCount` / `orgCount` 现全 0
  （库中无演示数据、`org_info.college` 也为空；收尾时把上一轮留下的那名测试学生删净了，`student_info` 现为 0 行）。

**⚠️ 主会话在这件事上先给错了建议**：我用 `.tmp-verify/bench-png-total.py` 测出「缩放反而更差（4.42 MB）」并撤回了缩放要求。代理 1 复核后指出我的脚本有**两个混淆因素**：① `:38` 写死 `Image.LANCZOS` —— 振铃在文字边缘造中间色，量化后仍压不动（单张实测 `student-home-1440` 491,118 B → **921,773 B，+87.7%**）；② `:36` 无条件 `w = 1280`，把 **620 宽的图放大**了 —— 这才是「620 高图爆炸 2.6 倍」的成因（它的脚本对宽 ≤1280 的图不放大，该文件入库 175,943 B，−61.9%）。
换成 **BOX（区域平均）** 后缩放到 1280 反而最优。**结论：缩放到 1280 保留，滤波器用 BOX，且禁止上采样。**

质量证据：量化后**同尺寸** PSNR **46.5~51.0 dB**，另做 3 处 1:1 局部裁剪目视比对（照片/表格/图表）；

### ③ B31：删除用户不级联 —— 已修并实测闭环

**口径（有硬证据，与任务书建议不同）**：被删学生的报名走**逻辑删除 `deleted = 1`**、**保留原 `status`**，
**不是**置 `CANCELED`。理由：看板「报名总人数」的口径是
`COUNT(*) FROM activity_signup WHERE deleted = 0`（`vcp-analytics/.../AnalyticsMapper.java:84`），
**`CANCELED` 行照样会被数进去** —— 只改状态的话删一个账号看板仍 +1，验收点（回到 10719）根本过不了。
保留原 `status` 还避免把「账号被删」伪装成「学生主动取消」，两者在审计上不是一回事。

**实现**（跨模块走依赖倒置，未破坏模块依赖规则）：
vcp-system 声明 `StudentSignupPurgePort` / `StudentDurationPurgePort` 两个端口
（照既有 `OrgLookupPort` / `OrgCollegeCountPort` 套路，**必需注入**而非可缺省 ——
缺实现时安静跳过就是"静默的半个级联"，正是 B31 的缺陷形态），
分别由 vcp-volunteer / vcp-certification 实现；编排在 `StudentArchivePurger.purgeByUserId`
（与建档的 `StudentArchiveRegistrar` 成对），由 `UserServiceImpl.deleteUser` 在同一个 `@Transactional` 里调用。
`signed_count` 用一条 UPDATE **按 `sql/09` 第 ⑦ 项的同一谓词重算**（而不是逐行 −1），天然幂等、不会多减漏减。
**顺带修掉同族缺口**：`PortraitAggregateMapper.selectTagCounts` 缺 `si.deleted = 0`（`student_profile` 无 `deleted` 列，
被删账号的画像快照仍计入标签分布；同 Mapper 其它查询一直都是这么过滤的）。

### ① 用户给的现象与我的第一反应（**别急着改代码**）

- 组织名墨迹 y 112–131，图例墨迹 y 110–122 → **图例底边比组织名高 8 个设备像素**

### ② 根因：只给子项写 `align-self:baseline` 拦不住匿名 flex item

`.panel-extra` 的 `align-items` 是默认 `normal`(=stretch)：整行里**只有**图例一个子项参与基线对齐，

用 Range(文字背景盒) + canvas `fontBoundingBoxAscent` 量基线：`org=208.6 / legend=203.6`，**差 5px**（100% 下）。

⚠️ 中途踩的坑：第一版探针往 `.panel-extra` 里插了个 `height:0` 的 inline-block 当基线探针 ——
插进去它**自己就变成一个 flex item**，量到的全是错的（orgB 报成容器顶边）。
改成 Range + canvas 才对。**量基线不要改 DOM，量盒子量不出基线。**

### 会话 14 补记（同日 21:2x）—— tab 条那条「右边的滑块」是一个 1px 溢出，不是样式设计
