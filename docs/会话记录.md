- **口令存储**：新增 `PasswordUtils`（BCrypt 强度 10）。口令读写全工程只经这一个类 ——
  登录校验、注册写入、管理员新增用户、本人改密、管理员重置五处。

- **登录失败锁定**：`LoginAttemptGuard` 内存 `ConcurrentHashMap`，连续 5 次失败锁 15 分钟、成功即清零。
  三个刻意取舍：单实例内存实现（重启即清空）、不落表列也不上 Redis、
  **对不存在的用户名同样计数**（否则「第 5 次会不会被锁」就成了账号是否存在的探针）。
  锁定判定排在**查库与口令校验之前**（否则锁定期间正确口令能登录，两条路径耗时差还会变成旁路信息）。
- **本人改密** `PUT /api/v1/auth/password`：改完踢掉该账号其它会话、**保留当前会话**
  （否则用户会以为改密失败）。
- **管理员重置** `PUT /api/v1/system/users/{id}/password`：口令可空（空即重置为 `123456`），
  重置后踢掉该账号**全部**会话 —— 重置的典型场景就是口令外泄。
- **新错误码** `ACCOUNT_LOCKED(20004)` / `OLD_PASSWORD_ERROR(20005)`，
  **刻意不进前端 `UNAUTHORIZED_CODES`**，免得被前端统一拦截成「登录已过期」。
- **前端**：新增共享组件 `ChangePasswordDialog.vue`，入口三处（学生个人中心「账号安全」、
  组织端/学校端控制台侧栏 —— 这两个角色没有个人中心页、这是他们唯一的自助改密入口、
  用户管理操作列「重置密码」）；`UserManageView` 初始口令框 `type="text"` → `password`，

### 本会话踩过的坑（下次直接照抄）

- **Maven 直连中央仓库超时**。解决办法：临时 settings 走阿里云镜像
  （`%TEMP%\vcp-settings-aliyun.xml`，本机无 `~/.m2/settings.xml`），命令：

  ```powershell
  mvn -s "$env:TEMP\vcp-settings-aliyun.xml" "-Dmaven.repo.local=C:\Users\lsy04\.m2\repository" `
      "-Dmaven.legacyLocalRepo=true" -DskipTests -B package
  ```

  `-Dmaven.legacyLocalRepo=true` **必须用双引号包住**，否则被 PowerShell 拆坏。
- **PowerShell 里 `$2` 会被当变量吃掉**：给数据库脚本传 BCrypt 密文时，SQL 一律用**单引号**包裹。
- **PS 5.1 按 GBK 读 `.ps1` 文件**，中文注释会导致解析失败 → 脚本里的标签用纯 ASCII。
- **查库输出的中文乱码**：`chcp 65001` + `[Console]::OutputEncoding = UTF8`，
  java 还要加 `-Dstdout.encoding=UTF-8`。
- **本机连云库要提权**：沙箱默认拦出网，`java -cp postgresql-42.7.13.jar ...` 会报
  `SocketException: Permission denied: getsockopt`，需以提权方式重跑。
- **浏览器自动化**：`tab.getAXState()` 偶发只返回空壳，`reload()` 后即正常；
  要拿输入框 `type` 这类 AX 树看不到的属性，用 `tab.playwright.evaluate(...)` 直接查 DOM。

#### ③ 修 B30：给注册链路补上 `college`（后端 8 个文件 + 前端 3 个文件）

- **缺陷**：`student_info` 的 `college` / `major` / `class_name` 三列**全后端没有写入入口** ——
  建档只写 `user_id`、占位学号（`S` + 六位零填充 userId）与 `total_duration`，三列恒为 null。
  而学院是**分组键**：`analytics` 的 `selectCollegeStats` 按 `college IS NOT NULL AND college <> ''` 分组
  （看板「各学院志愿时长排名」），学生档案列表与时长列表也各有「学院」列 —— 学院为 null 的学生全落进空分组。
- **本轮改法**（自上而下一条链）：
  ① `RegisterDTO` 加 `college`；
  ② `AuthServiceImpl.register` 校验它**必须命中字典的启用项**；
  ③ `StudentArchiveRegistrar.ensureArchive(userId, college)` 写进 `student_info.college`；
  ④ 前端注册表单加学院下拉，选项来自新接口。
- **口径：学院不接受自由文本。** 同一学院一旦出现第二种写法，「按学院统计」就会把它算成另一个学院 ——
  所以下拉框与校验**共用同一份字典**，学院清单不写死在代码里（加学院是数据维护动作，写死意味着要发版）。
- 两个容易踩的实现细节：
  - `StudentArchiveRegistrar` 的**两个重载各标了一次 `@Transactional`** —— 类内自调用不走 Spring 代理，
    只在双参方法上标注的话，管理员那条路径会**静默地跑在没有事务的连接上**，建档失败时账号已经提交，
    留下「有账号、无档案」的孤儿。

- **清空之前先备份，且备份要能还原**：本机没有 `pg_dump` / `psql`，JDBC 也能做（`COPY ... TO STDOUT` / `FROM STDIN`）。

  灌完**必须**把 `BIGSERIAL` 序列推到 `MAX(id)`（否则第一次插入就撞主键）。
- **`TRUNCATE ... RESTART IDENTITY CASCADE` 一把清 16 张表**：`RESTART IDENTITY` 让自增列归零，
  `CASCADE` 自动带上外键引用；只清数据、不动结构。
- **清库会清掉「增量脚本回填到行上」的值**：`05` / `06` 这类脚本执行过一次就不会自动重跑，
  重灌基础数据后要手动补跑（`sql/10` 头部已写明），否则字典色调、分类 code 这些「补出来的列值」会静默变空。
- **字典的「空类型」不能下推给 SQL**：`eq(dict_type, null)` 在 MyBatis-Plus 里是「不加条件」，
  传空值会返回全部字典项 —— 所以 `listByType` 里先挡空值。
- **类内自调用不走 Spring 代理**：重载方法要各自标 `@Transactional`，否则「看起来有事务」的那条路径其实没有。
- **加字段别顺手加 `@NotBlank`**：本轮的学院非空判定要查字典，注解表达不了；校验与文案都放 Service。
- **分组键不接受自由文本**：学院这类字段一旦出现第二种写法，「按分组统计」就分裂成两组；下拉与校验必须共用同一份字典。
- **验证脚本比代码先落盘时，别急着写「实测通过」**：本轮文档初稿写在打包重启之前，当时 jar 还是 13:37 那份、
  进程还是 pid 46468，于是初稿只能把「已修」限定在代码层面；打包重启后才补上 11/11 的实测结论。
  证据链要按 jar 时间戳与进程 pid 核，缺哪一环就写清楚缺哪一环。
