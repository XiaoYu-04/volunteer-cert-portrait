# 部署说明（D5）

> 目标：在一台**干净机器**上照本文档走一遍就能起来，前端路由刷新不 404。
> 本文档只讲部署；本地开发怎么起前后端见仓库根 `README.md` 的「新同学四步上手」。

## 0. 先选部署模式（两选一，只改一个变量）

| 模式 | 前端数据来源 | 需要后端 | 适用场景 |
|---|---|---|---|
| **A 真实后端**（答辩推荐） | 请求 `/api`，由 Nginx 反代到后端 8080 | 需要 | D5 验收口径；数据与云库一致 |
| **B 纯前端独立演示** | `src/mock` 本地模拟数据 | 不需要 | 后端没起来时的兜底 |

切换方式：改 `volunteer-cert-portrait-web/.env.production` 的 `VITE_USE_MOCK`
（`false` = 模式 A，`true` = 模式 B）。**页面代码一行都不用改。**

⚠️ 两种模式的数据**不是同一套**：模式 B 的 mock 数字（12,480 报名 / 86,420 小时）
与真实库（10,719 报名 / 19,319.3 小时）不一致，答辩材料里的数字必须标明是哪一套。

## 1. 环境要求

- JDK 21、Maven 3.9+
- Node `^22.18.0 || >=24.12.0`（见 `volunteer-cert-portrait-web/package.json` 的 `engines`）
- Nginx
- PostgreSQL：用云库即可，**不需要本地装库**

## 2. 后端

### 2.1 准备数据库

按顺序执行 `sql/` 下的脚本（顺序不能颠倒）：

```text
01_create_database.sql → 02_schema.sql → 03_init_data.sql
→ 04_demo_data.sql（演示数据，可选）→ 05_backend_gap_fix.sql（必执行）
→ 06_backend_gap_fix2.sql（必执行）→ 07_demo_scale.sql（演示数据放大，可选）
→ 08_password_bcrypt.sql（仅老库需要：把明文口令刷成 BCrypt 密文）
```

`05`、`06` 是接口的前置依赖（缺了 `05` 登录直接报错）；`07` 含 `activity_category.remark`
补列，**执行后必须重启后端**，否则分类接口会查不存在的列报错。

### 2.2 配置数据库凭证

凭证**不在仓库里**。两种给法，取其一：

```bash
# 方式一：环境变量（优先级更高）
export VCP_DB_USERNAME=postgres
export VCP_DB_PASSWORD='<口令>'
```

```yaml
# 方式二：放 jar 同级的 config/application-local.yml（模板见
#         volunteer-cert-portrait-server/vcp-boot/src/main/resources/application-local.yml.example）
vcp:
  db:
    username: postgres
    password: "<口令>"   # 必须加引号：以 0 开头的数字串会被 YAML 当成八进制（012345 → 5349）
```

### 2.3 构建并启动

```bash
cd volunteer-cert-portrait-server
mvn -B package -DskipTests

# 【生产必须带 prod profile】不带则第 3 节的三处收紧全部不生效
java -jar vcp-boot/target/vcp-boot-1.0.0.jar --spring.profiles.active=prod
# 等价写法：SPRING_PROFILES_ACTIVE=prod java -jar vcp-boot/target/vcp-boot-1.0.0.jar
```

> ⚠️ **后端正在运行时先停掉再 `mvn package`** —— 运行中的进程会锁住
> `target/vcp-boot-1.0.0.jar`，repackage 会报 `Unable to rename ... .jar.original`。

### 2.4 部署前必改一处

`application-prod.yml` 的 `vcp.cors.allowed-origin-patterns` 是占位域名
（`https://vcp.example.edu.cn`），改成实际前端域名。
**前后端同源（Nginx 反代）时该项不会命中**，但不要留着示例域名上线。

## 3. 验证 prod profile 真的生效（三条，缺一即说明没带 profile）

| 检查项 | 未激活 prod（开发口径） | 激活 prod 后应为 |
|---|---|---|
| 访问 `/doc.html` | 直接打开文档页（免登录） | 要求登录态，不再免登录 |
| 启动日志 | `com.vcp` 为 debug，全量打印 SQL | 为 info，不再打印 SQL |
| 跨域来源 | `*`（任意站点可带凭证跨域） | 收窄为白名单域名 |

## 4. 前端

```bash
cd volunteer-cert-portrait-web
# 1) 确认 .env.production 的 VITE_USE_MOCK 与第 0 节选定的模式一致
# 2) 构建
npm ci
npm run build          # 产物在 dist/
```

产物默认 `base` 为 `/`，即托管在域名根目录；若要放到子路径，需先改 `vite.config.js` 的 `base`。

## 5. Nginx

```nginx
server {
    listen       80;
    server_name  vcp.example.edu.cn;

    root  /var/www/vcp/dist;
    index index.html;

    # 【history 回退】刷新任意前端路由都不 404 —— 这是 D5 的验收项之一
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 【反代】不带路径的 proxy_pass：保持 /api 前缀原样转发到后端
    # 后端接口前缀本身就是 /api/v1/...，所以这里不要做任何路径重写
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # index.html 不缓存，否则前端发版后用户仍拿旧壳子
    location = /index.html {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
}
```

`proxy_pass` 写成 `http://127.0.0.1:8080/api/` 会把前缀重写掉，导致后端收不到
`/api/v1/...` 而 404 —— **不要带路径**。

## 6. 验收清单（照 D5 的定义逐条打勾）

- [ ] 在干净机器上照本文档走一遍能起来
- [ ] 前端路由刷新不 404（第 5 节的 `try_files` 生效）
- [ ] 三个角色都能登录：`student` / `org_admin` / `admin`（口令见根 `README.md`）
- [ ] 四个修复可见：分类管理页有「说明」、公告有正文、学生列表有年级、个人中心有手机号/邮箱
- [ ] `/doc.html` 要求登录（证明 prod 生效）

## 7. 常见坑（都踩过）

1. **不带 `--spring.profiles.active=prod`** → 文档页免登录 + CORS 全开 + SQL 全量打印，
   而且不会有任何报错提示，只能靠第 3 节的三条主动验证。
2. **缺凭证时应用仍能正常启动**（占位符解析不了会被当成字符串），要到第一次访问数据库
   才以认证失败暴露 —— 连不上库时第一件事是查 `application-local.yml` 是否存在、口令是否写对。
3. **口令不加引号**：`012345` 会被 YAML 当成八进制整数解析成 `5349`。
4. **跑过 `sql/07` 没重启后端**：分类接口查不存在的列报错。
5. **模式 A 但 Nginx 没反代 `/api`**：页面全空（接口 404），前端不会有明显报错提示。
6. **在 `volunteer-cert-portrait-server/` 下 `java -jar` 时读的是源码树里的
   `vcp-boot/src/main/resources/application-local.yml`**（该文件已被 pom 排除、不会进 jar）；
   部署到别的目录时请用 jar 同级的 `config/application-local.yml` 或环境变量。
