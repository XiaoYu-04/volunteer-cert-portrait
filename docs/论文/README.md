| 3 | 3.4.3 | **A3 的并发方案**：把判断条件下推到 `WHERE` 子句，一条 `UPDATE` 同时解决原子性与超卖，**不需要额外的 `version` 列** |

## 四、写作约定

### 4.1 引用格式

- 统一用 **`文件:行`**（如 `docs/待办清单.md:192-195`、`sql/02_schema.sql:327`、
  `StpInterfaceImpl.java:39-75`）。跨多行时给起止行号。
- 代码文件用**相对仓库根**的路径；同一小节内重复引用时可用"同上 `:123`"。
- **每个数字都要有出处**：本稿里出现的每一个实测数字（1500 / 386 / 10719 / 19319.3 /
  1503 / 389 / 90.1% / 75.6% / 22.6 / 59 / 72 / 70 / 29 / 31 / 73 / 20 …）都能追到来源。

### 4.2 状态字段一律用英文码

**所有状态、动作、字典键一律写英文大写码，不写中文**：

| 类别 | 正确写法 | 错误写法 |
|---|---|---|
| 活动状态 | `DRAFT` / `PUBLISHED` / `CLOSED` / `CANCELED` | 草稿 / 已发布 / 已结束 / 已取消 |
| 报名状态 | `PENDING` / `APPROVED` / `REJECTED` / `CANCELED` / `COMPLETED` | 待审核 / 已通过 / 已驳回 / 已取消 / 已完成 |
| 签到状态 | `NOT_SIGNED` / `SIGNED_IN` / `SIGNED_OUT` / `ABNORMAL` / `ABSENT` | 未签到 / 已签到 / 已签退 / 异常 / 缺勤 |
| 时长状态 | `PENDING_SUBMIT` / `PENDING_AUDIT` / `APPROVED` / `REJECTED` | 待提交 / 待审核 / 已通过 / 已驳回 |
| 组织状态 | `PENDING` / `APPROVED` / `REJECTED` / `DISABLED` | 待审核 / 已通过 / 已驳回 / 已停用 |
| 用户状态 | `ACTIVE` / `DISABLED` | 正常 / 已停用 |
| **审核动作** | `SUBMIT` / `APPROVE` / `REJECT` | 提交 / 通过 / 驳回 |

> ⚠️ **`APPROVED`/`REJECTED`（状态）与 `APPROVE`/`REJECT`（动作）不同形**，别混
> （`CLAUDE.md:101`、`sql/02_schema.sql:448`）。

### 4.3 三套数据口径不能混用

**这是本稿最容易写错的地方**，写作时务必逐处核对：

| 口径 | 数字 | 性质 | 出现场景 |
|---|---|---|---|
| **`sql/07` 口径** | **1500 学生 / 386 活动 / 10719 报名 / 19319.3 小时** | 真实数据库，`sql/07_demo_scale.sql` **提交那一刻**的口径 | 测试报告第 8 节的行数核对、`sql/07` 末尾自检输出、看板实测（386 / 10719 / 19319.3 / 90.1% / 75.6%） |
| **叠加 `sql/12` 后** | **1503 学生 / 389 活动**（报名与时长不变） | 真实数据库，**当前库中值** | 接口实测（`/activities` 389）、画像重算 `scanned=1503`、真后端逐页点检（看板 389 场） |
| **前端 mock 口径** | **12,480 报名 / 86,420 小时** | **不是真库数字**，纯前端独立演示用 | 只在讲"前端脱离后端独立运行"时提及，**必须标明不是真库数字** |

**为什么会存在两组真库口径**（`docs/测试报告.md:287-291`、`CLAUDE.md` 踩坑第 20 条）：

- 差 3 的学生 = `sql/12` 新建的 **3 个图文演示学生**；
- 差 3 的活动 = `sql/12` 新建的 **3 场带图活动（id 387/388/389）**；
- **报名与时长不变** —— `sql/12` **不造报名、不造时长**；
- `sql/12` 必须放最后（它给三场活动的名额是 20/35/18，
  先跑 `12` 再跑 `07` 会被 `07` 的"名额下限抬到 46"回填改掉）。

### 4.4 未做/受限项如实写

本稿涉及的四类"不完美"内容，**一律照实写，不用模糊表述掩盖**：

| 类别 | 本稿的处理 |

| **受限项** | 5.9.2 节给出定性分析（符合设计 / 契约一致 / 未实现），**同时保留测试报告的原始统计** |

### 4.5 图表约定

- **Mermaid 必须能通过解析**。本项目已验证的写法参考 `docs/ER图.md`：
  - `flowchart TB/LR/TD`，节点标签一律用双引号 `A["文本"]`，边标签 `-->|"文本"|`；
  - `stateDiagram-v2`，状态用英文码 ID，转移标签 `A --> B : 中文说明`；
  - `sequenceDiagram`，`participant X as 中文名`，`Note over A,B: 说明`；
  - `erDiagram`，属性行 `类型 名称 [PK|FK|UK] "注释"`，
    关系行 `表A ||--o{ 表B : "中文说明"`（实线有外键、虚线 `..` 无外键）。
- **两个已踩过的坑**：
  1. 节点/消息文本里**不要出现裸的 `<`**（会被当成 HTML 标签）—— 用 `&lt;` 或改写文字；
  2. 文本里**不要出现分号 `;`**。
  （本稿已用脚本扫描过全部 18 个 Mermaid 块，无此问题。）
- ASCII 图用于**目录树、脚本顺序、命令清单**这类不需要渲染的内容。
