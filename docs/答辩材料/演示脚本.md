## 二、演示总览与时间分配

**建议总时长 15~18 分钟**，三幕串成一条**完整闭环**：

```text
第一幕 学生报名  →  第二幕 组织审核 + 开时长  →  第三幕 学校终审  →  回到学生端看时长/画像变化
```

| 幕 | 角色 | 时长 | 核心看点 |
|---|---|---|---|
| 第一幕 | 学生 | 5 min | 活动浏览（含图文）→ 报名 → 我的时长 22.6h → 公益画像四星 |
| 第二幕 | 组织管理员 | 6 min | 发布活动（带图）→ 审核报名 → **签到窗口说明** → 开时长 |
| 第三幕 | 学校管理员 | 6 min | 数据看板（90.1% / 75.6%）→ 终审 → 画像 → 系统管理 |
| 收尾 | 回到学生 | 1 min | **时长增加、画像等级重算** —— 闭环成立 |

> **时间不够时的最小路径**（约 6 分钟）：第一幕只做「志愿活动 → 我的时长 → 我的公益画像」，
> 第三幕只做「数据看板」。**闭环演示是加分项，不是必选项。**

### 降级 A：后端挂了 / 连不上数据库 → 切纯前端 mock

| 项 | 内容 |
|---|---|
| **触发条件** | 8080 打不开、登录报网络错误、页面全空 |

| **⚠️ 必须同时改口（否则数字对不上，一问就穿）** | 「现在切到**纯前端独立演示模式**，数据是前端内置的演示数据集，**不是数据库里的那套**。这套的数字是**报名 12,480 人 / 累计志愿时长 86,420 小时**；刚才那套真实库是 **10,719 报名 / 19,319.3 小时**。两套不是同一个量级，请注意区分。」〔`volunteer-cert-portrait-web/.env.production:9`、`:12`；`dataset.js:34`~`:35`〕 |

| **能力边界（如实说）** | mock 模式下**写操作不会真的改后端数据** —— 报名、审核、开时长这些点下去只改前端内存/localStorage，**闭环演示做不了**。此时**只演示读页面**（看板、画像、列表），并说明闭环已在真实环境验证过。 |
| **mock 模式下的已知差异（别被问住）** | mock 里演示学生的等级是按序号循环取的，**与时长不挂钩**（原型如此）—— 要让 mock 与后端算法一致，会把演示账号从五星降到三星，所以没改。这是**已知差异**，如实说明。〔`volunteer-cert-portrait-web/src/mock/data/dataset.js:1061`~`:1063`〕 |

### 降级 E：演示中误删了用户

| 项 | 内容 |
|---|---|
| **触发场景** | 演示时手滑点了「删除用户」 |

| **口径提醒** | 修复后的删除口径是：报名走**逻辑删除 `deleted = 1`、保留原 `status`**，**不是**置 `CANCELED`（因为看板 `enrolled` 口径是 `deleted = 0`，`CANCELED` 行仍会被数进去）。这一点如果被问到，是很好的加分回答。 |
