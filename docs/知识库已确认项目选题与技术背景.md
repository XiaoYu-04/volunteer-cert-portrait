## 二、总体架构

**架构定位：前后端分离 + 后端"模块化单体（Modular Monolith）"** —— 适合三人小组：一个仓库、一次部署，但代码按业务域拆成独立 Maven 模块，答辩时能讲清"高内聚、低耦合"。

```

│  浏览器      │ ─────────► │ Nginx :80        │
│  Vue3 SPA   │            │ 静态资源 + /api 反代│
└─────────────┘            └────────┬─────────┘
                                    │ /api/v1 → 127.0.0.1:8080
                     ┌──────────────▼─────────────────────┐
                     │  volunteer-cert-portrait-server     │
                     │  Spring Boot 4.1.1 · Java 21        │
                     │  ┌───────────────────────────────┐  │
                     │  │ vcp-boot（启动）               │  │
                     │  │ vcp-system / vcp-org           │  │
                     │  │ vcp-volunteer / vcp-certification│ │
                     │  │ vcp-portrait / vcp-analytics   │  │
                     │  │ vcp-framework / vcp-common     │  │
                     │  └───────────────────────────────┘  │
                     └──────┬───────────────────┬──────────┘
                            │ JDBC              │ 可选
                     ┌──────▼──────┐     ┌──────▼──────┐
                     │ PostgreSQL  │     │ Redis       │
                     │ :5432       │     │ :6379       │
                     └─────────────┘     └─────────────┘
```

### 3.5 模块依赖规则（防乱用，答辩加分）

```
vcp-boot ──► 全部业务模块 + vcp-framework
vcp-analytics ──► vcp-certification、vcp-volunteer、vcp-portrait（只读聚合）
vcp-portrait ──► vcp-certification、vcp-volunteer（读取时长/参与数据）
vcp-certification ──► vcp-volunteer（校验报名/签到）、vcp-system（学生信息）
vcp-volunteer ──► vcp-org（组织信息）、vcp-system（用户/学生）
vcp-org ──► vcp-system
业务模块 ──► vcp-framework ──► vcp-common
```

规则：禁止反向依赖与循环依赖；跨模块只调用对方 **Service 接口**，禁止直接访问对方 Mapper/表；通知类耦合用 Spring Event 解耦。

### 3.6 全局技术规范

- **统一返回**：`{ code, message, data }`，成功 `code=0`；分页统一 `{ total, list }`。
- **错误码分段**：1xxxx 通用 / 2xxxx 认证权限 / 3xxxx 活动报名 / 4xxxx 时长认证 / 5xxxx 画像统计。
- **权限标识**：`域:资源:操作`，如 `system:user:list`、`volunteer:activity:audit`、`certification:duration:approve`。
- **接口路径**：统一前缀 `/api/v1/`（可结合 Boot 4 原生 API Versioning [10]）。
- **状态机枚举**（统一英文码存库 + 字典翻译，知识库已强调必须统一 [4]）：
  - 活动：`DRAFT / PUBLISHED / CLOSED / CANCELED` [3]
  - 报名：待审核 / 已通过 / 已驳回 / 已取消 / 已完成 [4]
  - 签到：未签到 / 已签到 / 已签退 / 异常 / 缺勤 [4]
  - 时长：待提交 / 待审核 / 已通过 / 已驳回 [4]
- **数据规范**：全表 `id`（BIGSERIAL）、`create_time/update_time` 自动填充；`snake_case` 命名；建议索引：`activity_signup(activity_id)`、`activity_signup(student_id,status)`、`attendance_record(signup_id)`、`service_duration(student_id,status)`、`volunteer_activity(org_id,status)`。
- **配置要点**（application-*.yml）：端口 8080、数据源与 Hikari 参数、MyBatis-Plus（驼峰、逻辑删除）、Sa-Token（token-name、timeout）、multipart 上传限制、日志级别。

### 4.4 路由与权限设计

- 三套布局：学生端 `/student/*`、组织端 `/org/*`、学校端 `/admin/*`，登录/注册用空白布局。
- 路由 `meta` 携带 `{ title, roles, perms }`；守卫流程：无 token → `/login`；有 token 无用户信息 → 拉取用户信息；角色不匹配 → `/403`。
- 按钮级权限用 `v-perm` 指令；菜单建议"前端静态定义 + 角色过滤"（毕设最稳方案）。
- Axios 封装：自动携带 `Authorization: Bearer <token>`；统一解包 `code`；401 自动跳登录；按 `api/` 模块拆分接口函数。

## 六、部署与协作

**端口规划**：前端开发 5173；后端 8080；PostgreSQL 5432；Redis 6379（可选）；Nginx 80；接口文档 `/doc.html`。

**部署方案**：
- 开发：Vite dev server 代理 `/api` → 8080，后端连本地 PG。
- 生产（最低要求）：`mvn -pl vcp-boot -am clean package` 打可执行 jar → `java -jar`（systemd 托管）；前端 `npm run build` 出 `dist` → Nginx 托管并反代 `/api` → 8080；PG 导入 `sql/volunteer_cert_portrait.sql`。
- 进阶（可选）：Docker Compose 编排 nginx + server + postgres + redis。

**Git 规范**（沿用知识库方案 [4]）：分支 `main / develop / feature/* / fix/*`；提交前缀 `feat / fix / docs / test / style / refactor`；文档统一放 `docs/`（需求分析、数据库设计、接口文档、测试用例）。

**开发顺序建议**：P0（登录权限 → 活动报名 → 签到 → 时长审核 → 基础看板）先落地，再做 P1（公益画像、通知、日志），P2（证书、收藏等）视时间取舍 [4]。
